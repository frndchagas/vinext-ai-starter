# Monorepo organization

## Choice

We will use Bun workspaces for JavaScript and TypeScript dependencies. Turborepo will be the task orchestrator. Laravel will remain a Composer project inside the same repository.

```text
.
├── apps/
│   ├── web/                 # Vinext and Bun workspace
│   └── api/                 # Laravel, Composer, and task wrapper
├── packages/
│   ├── api-client/          # client generated by Orval
│   └── config/              # shared configuration
├── turbo.json
├── package.json
├── bun.lock
└── apps/api/composer.lock
```

The `workspaces` field will include `apps/*` and `packages/*`. The API's `package.json` will expose Composer, Artisan, Pint, PHPStan, and PHPUnit tasks to Turborepo. The API's only own JavaScript dependency will be Multiplex, used by the official `artisan dev` command to coordinate local processes.

## Each tool's responsibility

Bun will install dependencies, resolve workspaces, and run the public root commands. Turborepo will order tasks and store deterministic results in the local cache. Composer and Artisan will remain responsible for the PHP work.

```text
bun run dev
bun run check
bun run check:full
bun run test:e2e
```

Contributors will use these commands without needing to call Turborepo directly in day-to-day work.

## Spike outcome

Nx was evaluated first because it models non-JavaScript projects with `project.json`. In the current combination, Nx 23.1.1 cannot process the version 2 `bun.lock` generated by newer Bun builds. The 23.2 line was still in beta during the spike and showed the same failure with the stable local installation.

Turborepo 2.10 read the same lockfile and recognized the four workspaces without special configuration. Keeping Bun current with a stable orchestrator is preferable to freezing Bun 1.3 or adopting an Nx beta.

## Turborepo boundaries

We will use Turborepo only for the graph, ordering, and the local cache. Version 0.1 will not have remote caching, custom generators, or Laravel plugins.

The cache will be restricted to lint, typecheck, unit tests, contract generation, and builds. Integration tests, E2E, migrations, queues, Reverb, and tasks with network access or external state will never use the cache.
