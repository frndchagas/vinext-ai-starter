# Frontend quality

## Component system

Shadcn/ui will be the component system. The base will be Base UI, which is now the default recommended by shadcn itself for new projects. Components will live in the repository and use Tailwind CSS 4.

Shadcn is not a closed component library. The CLI copies the code into the application, and Base UI provides the interaction and accessibility primitives. The starter will pin `base` in `components.json` and will not mix Base UI, Radix, and React Aria components.

Initialization will be non-interactive with a pinned version:

```text
bunx shadcn@<pinned-version> init --base base
```

## Standard verification

| Responsibility | Tool | Policy |
| --- | --- | --- |
| Formatting | Oxfmt | format differences block |
| Lint | Oxlint type-aware | configured errors block |
| Types | TypeScript | `tsc --noEmit` blocks |
| Unit tests | Vitest | failure blocks |
| Secrets | Gitleaks | confirmed secret blocks |
| Build | Vinext | `vinext check` and build block |

Oxlint will enable the native plugins `typescript`, `react`, `jsx-a11y`, `import`, `unicorn`, and `vitest`. Type-aware rules will cover promises, unsafe operations, and non-exhaustive switches. `react/react-compiler` will start as a warning while it remains experimental in Oxlint.

The starter will not run ESLint, Prettier, or Biome in parallel. An additional tool only comes in when it covers a concrete gap.

## Integration and E2E

- Testing Library will test observable behavior, without coupling tests to the implementation;
- MSW generated by Orval will mock the API in fast tests;
- Playwright will cover login, authorization, an asynchronous operation, and updates via Reverb;
- accessibility tests will verify the essential flows and keyboard navigation.

## Release diagnostics

React Doctor, Knip, and dependency-cruiser will run in `bun run check:full` and before releases. Versions will be pinned. React Doctor will send no telemetry or remote score in CI.

These diagnostics do not replace Oxlint, TypeScript, or tests. They identify architectural problems, dead code, and React patterns that deserve review.
